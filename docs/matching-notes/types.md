# Instruction differences that reveal types

Part of the [matching notes](../matching-notes.md). Add a lesson here when a function with this symptom teaches you something new: symptom, cause, fix, example.


- **A global pointer loaded as `lis; addi rX,rX,sym@l; lwz rX,0(rX)` into the argument register, then `mr r31,r3`,** where the target loads it straight into the saved register (`lwz r31,sym@l(r4); mr r3,r31`): the global is a `void*` and the local takes it through a conversion, `UnkTask* task = lbl_803CC1B8;` with `extern void* lbl_803CC1B8;`. A typed global lets MWCC copy-propagate the load into the call's argument; it showed only once a loop with a call kept `task` live. Example: `fn_3_912B4` in `rep_1610.c`.
- **`lha` followed by `extsh.` on the loaded value** (`lha r4,7016(r30); extsh. r0,r4`, where the base has `lha r0; cmpwi r0,0`): the field was read into an `s16` local and tested, `s16 hangtime = g_Ball.pitchHangtimeCounter; if (hangtime <= 0)`, and the local is reused later. Example: `fn_3_1EFE4` in `rep_8C8.c`.
- **`lha; extsh. r0,r5; sth r5,...` and then `extsh r0,r5` again before the value indexes an array:** the source stored an `s16` field and read the field back, `g_UnkThrowing_31ACC._0C = g_Ball.fielderWBallIndex; if (g_UnkThrowing_31ACC._0C >= 0 && g_Fielders[g_UnkThrowing_31ACC._0C]._203)`; MWCC reuses the stored register and re-extends it at each read. An `s16` local or the original field compiles without the second `extsh`. Example: `fn_3_62E70` in `rep_E08.c`.
- **`srawi rT,rX,31; xor rX,rT,rX; subf rX,rT,rX`** is MWCC's `__abs()` intrinsic. A call to `abs()` through `arith.h` stays a `bl`, since no header here maps it to the intrinsic. Example: `fn_3_22ABC` in `rep_A00.c`.
- **Signedness of an int-to-float conversion.** Signed: `xoris rX,rX,0x8000` with the double constant `0x4330000080000000`. Unsigned: no `xoris`, constant `0x4330000000000000`. Fix the element or variable type to match.
- **The int-to-float constant addressed with `addi rX,rY,sym@l; lfd f1,0(rX)` in the base, `lfd f2,sym@l(rY)` in the target, around an `int` scaled by a float:** the original used a compound assignment, `frames *= 1.3f; frames += 30;`, not `frames = (s32)(frames * 1.3f) + 30;`. Example: `fn_3_A6ABC` and `fn_3_A6810` in `rep_18E8.c`.
- **The int-to-float constant addressed with `addi rX,rY,sym@l; lfd f1,0(rX)` in the target, with the two conversions' stack temporaries in the other order, after `fn_3_1650C(&x, &y, ...)`:** the screen coordinates went through `f32` locals before the stores, `fx = x; fy = y; sprite->_48 = fx; sprite->_4C = fy;`. The float argument computed into the same local first, `fy = -2.0f - pos->_00C;`, moved the `-2.0f` load into place (found by the permuter). Example: `fn_3_95620` in `rep_16B8.c`.
- **A byte field stored from the register that holds `-1` for neighbouring halfword stores, where the base loads `li rX,255` for it:** the field is `s8`, not `u8`. Example: `g_FieldingLogic._125` in `fn_3_A9354` (`rep_18E8.c`).
- **A `u8` field converted with the signed constant** (`lbz` then `xoris`): the value went through an `int` local first. `alpha = p->color[3]; alpha -= 255.0f / n;` converts signed; `alpha = p->color[3] - 255.0f / n;` converts the `u8` as unsigned. Example: `fn_3_16C548` in `rep_4090.c`.
- **`lwz; rlwimi rX,rY,0,24,31; stw` where the base has a single `stb`** (the low byte of a word replaced): the field is a `u32` updated with an explicit mask, `s->_58 = (s->_58 & 0xFFFFFF00) | alpha;`. An 8-bit bitfield at a byte boundary compiles to `stb`. Examples: `fn_3_99C88` and the alpha loops in `rep_1770.c`. A constant low byte follows the same rule: `lwz; clrrwi rX,rX,8; ori rX,rX,255; stw` is `s->_58 = (s->_58 & ~0xFF) | 0xFF;`, and `lwz; clrrwi; stw` is `s->_58 &= ~0xFF;`; `s->_58 |= 0xFF` drops the `clrrwi` (`fn_2_7207C` in menus `rep_0C50.c`).
- **`subfic r0,r0,K; cntlzw r0,r0; srwi. r0,r0,5; beq` where the base has `cmplwi r0,K; bne`:** the condition is a ternary, `x == K ? TRUE : FALSE`, here returned by a `static inline` helper; a plain `==`, `(x == K) != 0`, a `BOOL` local or a cast all compile to the compare and branch. Example: `isAnimDone` in `fn_3_99E10` (`rep_1770.c`). Pass the helper the array expression itself, `isAnimDone(lbl_80371C30[task->_14]._00)`; with a local pointer as argument it compiles to the compare again, and CSE still reuses the loaded pointer for a later store through the same expression (`fn_3_120FF8` in `rep_3448.c`).
- **`lhz rX; addis r0,rX,0; cmplwi r0,0xFFFF` where the base has `cmplwi rX,0xFFFF`:** a `u16` value went into an `s32` local before the test, `s32 id = p->_162[3]; if (id != 0xFFFF)`; a `u16` local compares directly. Where the target also masks the index (`rlwinm r0,rX,2,14,29`) but passes the value to a `u16` parameter with a plain `mr`, the source indexed with `(u16)id`. Examples: `anim` in `fn_2_8D024` and the bone ids in `fn_2_8D270` (menus `rep_0F60.c`).
- **A local loaded from a `u8` field, compared with `cmplwi` and used as an index with a plain `slwi`:** the local is `u32`. An `s32` local compares with `cmpwi`; a `u8` local masks the index with `rlwinm`. Example: `stadium` in `fn_3_16C410` (`rep_4090.c`).
- **`neg; andc; srwi rX,rX,31; subf` on an `s32`:** a decrement that stops at zero and leaves negative values alone, `x -= x > 0;`. `if (x > 0) x--;` branches. Example: the hold timer in `fn_3_67A48` (`rep_EA0.c`).
- **`neg; or; rlwinm rX,rX,2,30,30` turning a 0/1 flag into a halfword-array offset** (where the base shifts the flag with `rlwinm rX,rY,1,...`): the index was converted to a boolean again, `tbl[flag ? 1 : 0]` (`tbl[flag != 0]` compiles the same). Example: `lbl_3_common_bss_35154._47A` in `fn_3_697CC` (`rep_EA0.c`).
- **`fmuls` then `fadds` in the target, `fmadds` in the base:** the multiply was its own statement, `height *= 0.003f; rot.y = fn(rot + height);`. Example: `fn_3_692E0` (`rep_EA0.c`) Products stored into a local `Vec` and then added stay separate as well, with an `fadds` of `0.0f` for the zero component: `offset.x = dist * cosf_kludge(a); ...; offset.z = 0.0f; p->pos.x = e->_24.x + offset.x;` (`fn_3_14B248` in `rep_3880.c`).
- **Array shape from index arithmetic.** `subfic r0,e,3; slwi; lwzx` from a struct's start is one 4-element array indexed `[3 - e]`, not two 2-element fields. Example: `trajOptions_s._0` must stay `s32[4]`.
- **`extsb` before a call only in the target:** the callee takes `int`, and the caller sign-extends its `s8` argument; with an `s8` parameter the callee extends instead. Example: `fn_8001B728(s32, s32, Vec*)`.
- **A flag parameter tested with `clrlwi. r0,r4,24`** is a `u8`; a `BOOL` (`int`) compiles to `cmpwi`.
- **`cmpwi r3,0` after a call where the base has `clrlwi. r0,r3,24`:** the callee returns `BOOL`, not `bool` (`u8`). Its own result local must be `BOOL` too, or `return ret;` gains a `clrlwi r3,rX,24`. Example: `checkTriangleCollisions` in `rep_D0.c`.
- **`clrlwi r3,r0,24` after an inlined callee's `li r0,1` only in the base:** the inlined callee returns `BOOL` while its caller returns `u8`; give the callee the caller's return type. Example: `fn_3_E28DC` and `fn_3_E29B4`, inlined into `fn_3_E2B70` (`rep_2998.c`).
- **A parameter the callee compares, switches on or scales as an index with no `clrlwi` or `extsb`** is int-width: MWCC extends a `u8` or `s8` parameter before each such use. A caller that passes a variable to it with a plain `mr` holds that variable in an int-width local too, even if the local is only loaded with `lbz` and stored with `stb`; a `u8` local and an `s32` parameter add `clrlwi`. Use this to type a callee from an unmatched unit, where the caller's constant arguments say nothing. Examples: `streak` in `fn_3_16230C` and `fn_3_76D08` (an `s32` local in `fn_3_77914`), `fn_3_B9BB4`'s `stadium`, `fn_3_8BBC4`'s fourth argument.
- **`extsb` before `cmpwi rX,-1` but none before `cmpwi rX,1` on the same field:** the field is `s8`; MWCC drops the sign extension when testing equality with a non-negative constant. Example: `AIStruct.aiPitchDirectionInput` in `fn_3_20CEC`.
- **`cmplw` between two computed element addresses:** the source compares two arrays, which decay to pointers. Keep the original's bug. Example: `g_Scores._04[batting] > g_Scores._04[fielding]` in `fn_3_212A0`.
- **`extsh rX,r3` right after a call that returns `s16`, where the base has `mr rX,r3`:** the result went into an `int` local, `int cur = radToShortAngle(x);`. The `int` local also keeps later `cur -= 0x280;` in its own register and extends it once at the call that takes it back as `s16`. Example: `fn_3_6AF9C` in `rep_FE0.c`.
- **`extsb` right after the `lbz` of an `s8` field, before an early test:** the field is read into an `int` local (`s32 idx = player->_254;`). An `s8` local delays the sign extension to its first use. Example: `fn_3_168CD8` and `fn_3_16892C`. The same goes for a value only stored back to an `s8` field: `bonus = tbl[x]._9[0]; bss->_49 = bonus;` with an `int` local gives the target's `extsb` before the `stb` (`fn_3_164A74` in `rep_3DA8.c`). Typing such a local `s8` also changed whether MWCC unrolled the loop that stores it: `fn_3_16440C` kept its 9-iteration loop rolled, as in the target, only with `s32 bonus`.
- **An `s8` tested with `extsb. r0,rX`, then extended again into a saved register** (`extsb r19,r5` scheduled into the next load) that indexes arrays and is passed to a call: an `s8` local copied into an `int` local after its guard, `idx = g_Minigame.minigameFielderIndex[i]; if (idx < 0) return; f = idx;`. Example: `fn_3_E1478` in `rep_2940.c`.
- **A loop pointer advanced by a stride no field explains** (`addi r8,r8,9` with fixed offsets such as `0x19EA(r8)` and `0x19EF(r8)` into a global): the header's flat fields there are an array of structs of that size. Check that no source uses the flat names, restructure the header, and run `match.py` on every user. Example: `MiniGameStruct._19E8[4]` (9-byte elements) and `MiniGameControlStruct` (`[4]` arrays up to 0x18F8, not two 0x16-byte structs) for `rep_2940.c`.
- **`extsh` of a converted value right before its halfword store, only in the target** (`fctiwz; stfd; lwz r0; extsh r0,r0; sth r0`), while an earlier value of the same variable is tested with `extsh.`: the local is an `int` assigned through an `s16` cast, `int magnitude = (s16)(64.0f * m / 56.0f);`. An `s16` local drops the extension before the store. Example: `fn_3_6CD88`.
- **`extsh` of a product only in the base** (`mullw r8,r0,r6; extsh r9,r8` before `cmpw` against a halfword field, then `neg` and `sth`): the local holding the product is `int`, though every value it receives is a halfword. Example: `points` in `fn_3_D8CD0` (`rep_28A8.c`, 98.4% to a match).
- **`srawi` kept in front of the `rlwinm` that packs a colour byte into a halfword** (`lbz; srawi r0,r0,3; rlwinm r0,r0,11,16,20`, where the base merges both into `rlwinm r0,r0,8,16,20`): MWCC merges the shift into the mask whenever it can see that the value came from a `u8`, through `>>`, `/`, a local or an `(s8)` cast alike. A `u16` cast between the shift and the packing stops it: `*(u16*)data |= ((u16)(c->g >> 2) << 5) & 0x7E0;`, and `(u16)(c->b >> 3) & 0x1F` for the low field. Example: `fn_3_E5FEC` in `sta_c6.c`.
- **`rlwinm r0,r0,16,24,29` on a halfword loaded with `lhz`** (a field taken from bits that a `u16` does not have): the source masked before shifting, `(*(u16*)src & 0xFC0000) >> 16`. `((*(u16*)src >> 18) & 0x3F) << 2` folds to 0 and the base stores `li r0,0`. The other fields of the same decoder were written the same way, `(x & 0xF800) >> 8`. Example: the RGBA6 case of `fn_3_E5E70` in `sta_c6.c`.
- **`andi.` with a mask where the base has `rlwinm`** (`andi. r0,r3,0xffbf` against `rlwinm r0,r3,0,26,24`): the source clears the bit with a literal of the field's width, `x &= 0xFFBF;` for a `u16`, `x &= 0xFD;` for a `u8`; `x &= ~0x40` compiles to `rlwinm` for both. Examples: `fn_3_6D304`, `fn_3_1690C0`.
- **`rlwinm rX,rX,16,8,15` where the base has `slwi rX,rX,16`, then `rlwimi` inserts** (bytes packed into one word): the source masks each byte before shifting, as a color-packing macro does: `((r & 0xFF) << 24) | ((g & 0xFF) << 16) | ((b & 0xFF) << 8)`. Plain shifts, `(u32)` casts and a `GXColor` local filled field by field all differ. Example: `PACK_RGB` in `fn_3_15F648` (`rep_3C80.c`).
- **`extsh` of an `s16` local right before a call only in the target** (`extsh r4,r31` where the base has `mr r4,r31`): the callee's parameter is `int`, as with `extsb` above. Example: `fn_3_76D08` and `fn_3_16230C`, called from `fn_3_77914` (`rep_12D0.c`).
- **A compare of a constant just assigned kept in the target** (`li r4,3; cmpwi r4,3; bne` for `type = 3; if (type == 3 && ...)`), folded away in the base: the variable is `s32` (`long`), not `int`; MWCC does not fold compares of `long` locals, as with the entry tests of constant loops. The same change moved `type` from r3 to the target's r4. Example: `fn_3_7BC20` in `rep_12D0.c`, which also needed `batter = &g_Runners[0];` inside `if (type == 3) { ... }` to form that address before the first test.
- **`addi r0,rX,1; cmplwi r0,1` with no `clrlwi` in the target** (`state == -1 || state == 0` merged into a range check): the local is `s32`, even though it is loaded with `lha`; an `s16` local adds `clrlwi r0,r0,16`. Example: `state` in `fn_3_78AC4` (`rep_12D0.c`). The same range test on an unsigned value (`addi r0,r3,-9; cmplwi r0,1; ble` after `clrlwi r3,r3,25`) came from `u32 type; ... type &= 0x7F; if (type != 1 && type != 6 && type - 9 > 1)`; a `switch` on the four values gave a compare tree, and `type < 9 || type > 10` two compares (`fn_3_A9354` in `rep_18E8.c`). A chain of equalities becomes the range check too: `result == 7 || result == 8 || result == 9 || result == 10` gave the target's `addi r3,r29,-7; cmplwi r3,3; ble`, where `result >= 7 && result <= 10` gives two compares (`fn_3_76D08` in `rep_12D0.c`, which uses both forms).
- **A `u8` copy of a value.** `clrlwi rX,rY,24` before comparisons can mean the code compares a `u8` variable assigned from a cast (e.g. `u8 starType = (s8)field`), not the field directly.
- **A `u8` field's value masked where the base uses a constant** (`li r27,1` kept in a saved register, then `clrlslwi r24,r27,24,2` to index a table with the field after an inlined call reads it back, while the base has `li; slwi`): the field was assigned from an `int` variable with a post-increment, `ribbon->colorFrom = color++; ribbon->colorTo = color;`. Assigning constants, or `color++` as its own statement, lets MWCC propagate the constant. Example: `fn_3_16B884` in `kinoko.c`.
- **`extrwi. r0,r0,1,24` testing one bit where the base has `rlwinm. r0,r0,0,24,24`:** the source shifted, `(stats >> 7) & 1`, instead of masking with `stats & 0x80`. One function can mix both forms: `fn_3_6E24C` (`rep_1188.c`) tests bits 7 and 1 by shifting and bits 0, 2 and 6 by masking.
- **`neg` before `cntlzw` only in the base:** a pointer tested with `p == NULL` inside a `|` chain. Write `!p`, which compiles to plain `cntlzw; srwi`. Example: `fn_3_16E1EC`.
- **A float's absolute value compared with a double constant in the other operand order** (`fcmpo cr0,f1,f0` with the constant in `f0` in the target, `fcmpo cr0,f0,f1` in the base): the source used `fabsf(dx) > 0.01`, not `fabs(dx) > 0.01`. Example: `fn_3_13FC24` in `rep_36D8.c`.
- **`fmuls` then `fadds` for a squared distance where the target has `fmuls` then `fmadds`:** `SQ(a.x - b.x) + SQ(a.z - b.z)` passes each difference through the macro, which MWCC does not fuse; the source computed the differences into locals first, `dz = ...; dx = ...; dolsqrtf2(dx * dx + dz * dz)`. Example: `fn_3_13F8C4` in `rep_36D8.c`.
- **An inlined callee's `BOOL` result tested with `clrlwi.` in the target** (`li r0,1` ... `clrlwi. r0,r0,24`, where the base has `cmpwi r0,0`): the callee returns `bool`, which still compiles to `li r3,1` standalone. Example: `fn_3_13D578`, inlined into `fn_3_13C7BC` (`rep_36D8.c`).
- **A call's float result as the second operand** (`fmul f0,f0,f1` or `fcmpu cr0,f0,f1` in the base, `f1,f0` in the target): swapping the C operands changes nothing. The source used another operation: `acos(x) / 2.0f` becomes `fmul` by the double 0.5 with the call result first, and `if (PSVECMag(v))` or `if (!PSVECMag(v))` compares the result first against 0.0, where `== 0.0f` puts the constant first. Examples: `fn_3_CAF9C`, `fn_3_169E70` in `kinoko.c`. The same holds for a float variable: `if (dir)` gives `fcmpu cr0,f31,f0` with the variable first, while `if (dir != 0.0f)` puts the constant first (`fn_3_15C024`).
- **`mulhwu` by `0xB21642C9` and `mulli 23` on a `rand()` result:** an unsigned modulo, `rand() % (sizeof(table) - 1)` for a 24-byte table of 23 entries plus a terminator. Example: `lbl_3_data_28558` in `rep_3E58.c`.
- **A `GXColor` argument loaded from `.rodata` straight into its by-value copy** (`lwz r0,lbl@l(r5); stw r0,8(r1)` before the call), where the base fills a local's own slot and then copies it (`stw r0,12(r1)` ... `lwz r0,12(r1); stw r0,8(r1)`): the argument is a `static const` object, `static const GXColor black = { 0, 0, 0, 0 };`, not an initialized local. Example: `SetFog`'s color in `fn_3_5C68` (`rep_1C0.c`).
- **A word loaded from `.rodata`, stored to the stack, reloaded after a call and written to the FIFO** (`lwz r0,lbl@l; stw r0,8(r1)` ... `lwz r0,8(r1); stw r0,-0x8000(r3)`): a local `GXColor color = { 0xFF, 0xFF, 0xFF, 0xFF };` sent with `GXColor1u32(*(u32*)&color)`. Example: `fn_3_16D810`.
- **`li r0,0; cmpwi r0,10; bge <after>` before a fully unrolled constant-count loop:** the counter is `s32` (`long`), not `int`. With `int i` MWCC folds the first test away; `s8`, `u8`, `s16`, `u16` and `u32` all differ further. The guard also keeps the stores before it in place. Example: `fn_3_112230` in `rep_31F0.c`.
- **`subfic r0,rX,3; cntlzw; srwi. r0,r0,5` whose result is tested twice by two `if`s:** a `BOOL` local, `BOOL barrel = g_Minigame.GameMode_MiniGame == MINI_GAME_ID_BARREL_BATTER; if (barrel) ...; if (!barrel) ...;`. Comparing a `u8` local in each `if` gives `cmplwi` twice, and building the `BOOL` from the `u8` local rather than the field moved two registers (the permuter found it). Example: `fn_3_1118B4` in `rep_31F0.c`.
- **`clrlwi rX,rY,16` before passing a parameter on to a `u16` parameter** (`GXInitTexObj`'s width and height): the function's own parameter is int-width, `u8* fn_3_B9534(s32 width, s32 height, GXTexObj* obj)`; a `u16` parameter is passed with `mr`.
- **`clrlwi r3,r0,24` after computing an argument (`addi r0,r3,4`) only in the base:** the callee's parameter is int-width even though the callee only stores it with `stb`; a `u8` parameter makes the caller truncate `u8 + K`. Example: `fn_3_B1DA4(int, int)` (rep_1B20), called as `fn_3_B1DA4(g_Practice.practiceLevel + 4, 1)` from `fn_3_B0464` in `rep_1AD0.c`.
- **`cmplw` between a parameter and a `u8` field** (`lbz r0,152(r26); cmplw r25,r0`): the parameter is `u32`; an `s32` compares with `cmpw`. Example: `fn_3_B8828` in `rep_1D58.c`.
- **A run of byte stores of -1 where the base loads the constant twice** (`li r8,255` for some fields beside `li r4,-1` for the others, every register after it shifted, where the target stores one `li r7,-1` everywhere): the fields stored with 255 are `u8` in the header but `s8` in the original. Other units' code confirms it (`lbz; extsb; cmpwi r0,-1` on the same offset). Example: `g_Minigame._1A0C` and `_1A2C` in `fn_3_DFA20` (`rep_28A8.c`).

- **`fmuls; fmuls; fadds` for a sum of squares where the base has `fmuls; fmadds`:** the squares were their own statements, `dx2 = dx * dx; dz2 = dz * dz; dist = dolsqrtf2(dx2 + dz2);`. `dx *= dx` gives the same instructions with the square in `dx`'s register. In the same loop, coin physics constants read from a table in place (`vel.y -= k[0]; vel.x *= k[1];`), which MWCC hoists, matched where locals assigned before the loop rotated two address registers. Example: `fn_3_D9EA0` in `rep_28A8.c`.
- **An `s8` field compared without `extsb` while the other operand is extended** (`lbz r0,0x19c6(r3); lbz r3,0x1905(r3); extsb r0,r0; cmpw r3,r0`), though the same field is extended where it indexes: the comparison casts it, `(u8)g_Minigame.rosterID != g_Minigame._19C6`. Example: `fn_3_DDD60` and `fn_3_DD3FC` in `rep_28A8.c`.
- **`addi r3,r3,1; clrlwi r0,r3,24; stb r3,...; extsb r0,r0; cmpwi r0,3`** (an `s8` field incremented, then tested through its truncated value): the increment is its own statement, `x++; if (x >= 3)`; `if (++x >= 3)` extends the sum directly. Example: `fn_3_DC5A4` and `fn_3_DCA68` in `rep_28A8.c`. A decrement tested for `< 0` likewise: `x--; if (x < 0) x = 12;` (`subi; clrlwi; ...; extsb.`), not `if (--x < 0)` (`fn_3_AF5A4` in `rep_1A80.c`).
- **`rlwinm r0,r0,3,13,28` in the base where the target scales a `u16` index with `slwi r0,r0,3`** (`lhz r0,20(r31)` of `task->_14`, then `lwzx` from a sprite table): the base reused the scaled index of a plain `table[task->_14]` and kept its 16-bit range; the target formed it as `task->_14 + i` with an unsigned `i` that is 0, through an inline helper, `static inline u32 getFrame(UnkTask3448* task, u32 i) { return lbl_80371C30[task->_14 + i]._00->_5C >> 16; }`.
