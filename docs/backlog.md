## Tools

- **Which matched functions an unmatched one inlines.** Several large functions in batch 9 (rep_08E8's `fn_2_4D960`, `4DC24`, `4DEE8`, `4D67C`, `4CB94`, `481F4`) were built from inlined copies of functions that already matched and matched on the first try; only the assembly showed it. A `match.py` listing like "waits on" that names the matched functions whose bodies appear in an unmatched one would flag them.
- **m2c and jump tables:** `match.py --m2c` fails with "Unable to determine jump table" on some functions (challenge rep_02A8's `fn_1_A95C`), and m2c run by hand on a patched copy rejects the `.ctx` ("Directives not supported"); applying the notes' workaround inside `match.py` would save the detour.
- **`regress.py` and new units:** its strict-match check compares only units the base report has, so matches in a unit new on the branch (all of batch 13's main-DOL units) are not counted or guarded; a later branch that breaks one would pass. Compare new units by name with the branch's report, or treat a unit missing from the base as all-missing.
- **`variants.py` gaps that cost batch 13 time:** no mode moves one declaration across every position or tries pairwise swaps (three workers wrote their own hill climbers, `build/scratch/movevar.py` in rep_3520's worktree); markers cannot be linked, so one loop-counter choice across many uses multiplies out (3^12 in rep_37A8); `--sample 700` still printed 5,040 variants; a batch reported "300 failed to build" without showing a compiler error; the top-N list includes variants that drop other functions, with no "best without drops" line; and applying a winner means copying it back by hand (a write-back for one function would help).
- **Parallel permuter runs:** `permute.py` setup deletes earlier output folders of the same function in the shared `~/.local/share/decomp-permuter`, so two worktrees permuting one function would collide; a per-worktree directory would avoid it.
- **Insert a function at its address.** Three workers in batch 10 put a new function on the wrong side of its neighbour in a reverse-ordered file; `match.py` now prints an `order:` line for it in both forms, but placing it by hand still costs a run. A `tools/` command that inserts a draft under the right `.text` line would avoid that.
- **`check_prototypes.py` and redundant `void(void)` externs:** it counts a header's `void(void)` as a placeholder, so a local `void(void)` extern that repeats it is never listed; batch 12 removed 123 of them by script, and 31 remain where including the header conflicts.
- **`variants.py`:** its score hides a change in a function's length (rep_13B8's top variant was 12 bytes too long), its sites are numbered in file order rather than template order, markers do not nest, and `--header` replaces the header for the baseline build too, so a template that changes a prototype fails.
- **`match.py` unit names:** `challenge/rep_0010` is ambiguous; only `challenge/challenge/rep_0010` works.
